# 识别流程精简方案

采用已批准的单轮名称清单方案。替代方案“只缩短 JSON 字段”仍保留重复流程；纯正则无法保持人名地址与任意简称能力，均不采用。

数据流：原文件读取 → 文本与共享上下文整理 → 每批一次模型请求 → 本地定位名称及少量歧义例外 → 固定规则一次识别 → 保存文件及映射 → 本地核对实际写回。

模型回答按行、制表符分隔：机构及其原文称呼、人名、地址。只有同形普通词和同名不同主体需要带原文块与摘录的例外行。例外以【原词】标定原文中的目标，不要求模型计算偏移或出现次数。所有原词、例外摘录和主体引用在本地验证；合法行继续使用，错误行报告未完成，不整批纠正重发。合法空结果用“无”，空白、截断不能伪装成完整成功。

输入仅跳过固定规则负责的纯数字块；连续完全重复文本压缩并保留原始位置对应；同一上下文只发送一次。正文及语境按约 24,000 字分批，另附短提示和当前批涉及的已知名称关系；不再将文本批次与机构资料组做笛卡尔组合。跨批继续携带已知精简名称并在最终本地定位时统一关联；不能任意截断原文或丢弃后批。

沿用现有识别结果、映射、原格式保存与还原。删除生产调用中的模型复查；文件保存后重读检查实际替换仍保留。网络错误保留有限重试；评测工具记录包括失败尝试在内的真实请求耗时。不新增缓存框架或依赖。

真实试验后调整：同一摘录允许多个【原词】标记，由本地展开；空类别横线、固定清单表头和唯一块编号的省略前缀可直接读取。同一块某称呼只有一个模型明确归属时沿用该归属，普通词排除和逐处归属优先；同块多个归属则不能推断未标明位置。DeepSeek 完全关闭思考的快速试验出现漏检和误检，故正式版使用官方低强度思考参数，每批仍只有一次识别，不恢复复核链。官方参数依据：https://api-docs.deepseek.com/guides/thinking_mode/ 。
