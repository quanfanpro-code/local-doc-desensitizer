# 独立复核问题修复设计

需求来自已完成复核及用户“修复所有问题，提交推送”的明确授权。采用下列方案 A，延续已在复核中给出的修复方向。

| 方案 | 成本、风险与兼容性 |
|---|---|
| A：在现有流程修复，移植少量已有上游规则 | 不加运行依赖；保持文本块、位置、映射及扫描 MD 行为；可逐项验收与回滚，采用 |
| B：整体接入 Presidio/JioNLP 框架 | 增加模型/运行依赖和迁移面，仍不能自动解决公式、脚注和 PDF 写回问题，不采用 |
| C：扩大 LLM 至所有数字类别 | 增加调用成本，无法解决未读入内容和文件写回，且纯正则仍需修复，不采用 |

## 数据流与错误处理

固定规则在保留原文偏移的 NFKC 视图上提取，复用 JioNLP 车牌字符和分隔点模式、Presidio MAC 同分隔符模式，适配 ASCII 边界允许中文相邻。明确账号字段与银行卡校验分开；金额利用当前列字段和近邻标签，复用 Decimal 计算；身份证分隔只影响校验视图，原文跨度保留；日期用标准库校验有效日历。

出现合并先验证位置。在规则与模型范围相交时，完整固定值必须保留；部分重叠的模型记录不能直接覆盖，也不能把有歧义的残余当可靠姓名，明确记录冲突。既有同位置不同机构冲突规则保留。

Word 对通用脚注、尾注 Part 用 python-docx 自带 XML 部件能力加载并在保存时序列化，不额外压缩包字符串替换。Excel 用已安装 openpyxl Tokenizer 将 TEXT 常量作为独立文本块，保留公式 token 序号；写回按单元格汇集常量替换与计算值替换，原公式记录一次。能保留公式时优先保留，计算敏感结果不能安全通过常量修正时只转换该格；引用不作为普通文字常量。公式块不能污染导出的显示文本。

PDF 使用 PyMuPDF 提取的字符位置，以字符内部小区域触发原生清除，清除与插入区域分开，避免扩大清除范围；实际输出核验包含未修改文字。含大面积扫描图与 OCR 的页进入既有扫描 MD 分支；可直接利用已有 OCR 文字时避免重复依赖服务，无法读取时使用配置的 OCR。

GUI 将 OCR 与 LLM 前置能力分别判断，文字 PDF 参与纯正则降级，混合批次可跳过不能 OCR 的扫描件；取消还原优先显示取消状态。原有后台预检与取消机制不重构。

## 验证与回滚

每项使用独立手算预期和已有复现材料先失败再修复。固定规则校验正例、边界与反例；Word/Excel/PDF 通过真实保存再读取核验，还原和原件哈希共同验收；模型错误边界用可控回复，真实质量另用原授权在线接口复测。全量测试、代码解析、差异检查、许可与密钥扫描后提交。修改前全仓已备份到用户 BackUp，发布回滚通过新的反向提交进行，不重置共享历史。
