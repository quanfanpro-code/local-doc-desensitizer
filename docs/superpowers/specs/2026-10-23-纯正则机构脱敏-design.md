# 纯正则机构脱敏设计方案（2026-10-23）

## 一、目标回顾

主界面新增"识别方式"选择：LLM 或纯正则。纯正则在本地用后缀正则、脱壳与声明简称完成机构脱敏，不调用模型；LLM 模式行为不变，仅在模型不可用时把"继续"改为走纯正则机构脱敏。人名与详细地址不属纯正则范围。

## 二、现状约束（已核实）

- `主程序/脱敏处理器.py` 104-106 行：`跳过模型` 为真时直接给空结果，机构、人名、地址全部跳过。
- `主程序/文档识别.py` 160-188 行：正则只作候选，且候选仍需模型复核。
- `主程序/ner引擎.py` 保留 `_规则识别明显机构`、`判断机构子类型`、`全局映射表`；`_清洗实体名`、`_洗行业词`、`_查找父实体`、`_发现简称候选`、`_合并简称声明` 已在 2026-09-19 删除。
- `主程序/定位写回.py` 23-50 行 `准备替换`：`类型 == "Ni"` 的出现项走 `注册机构称呼`，同一机构的全称得主代号、其他称呼自动得圈数字后缀，天然实现全称与简称分别还原。因此纯正则只需产出正确的机构表与出现记录，替换、写回、还原、映射保存全部复用。
- `主程序/app.py` 643-658 行：模型不可用弹窗，选继续后置 `processor.跳过模型 = True`。
- 历史实现位置：`2fbf1a0` 的 `ner引擎.py` 1080-1254 行为正则兜底主流程，742-813 行为脱壳与查找函数，876-954 行为简称模式；`3e7bac9` 的 `ner引擎.py` 1216 行起为简称声明模式。

## 三、方案比较

### 方案一：新增独立模块 `主程序/正则机构识别.py`（推荐）

内容为单个入口 `识别正则机构(块列表, 进度回调=None) -> 识别结果`，内部完成全称识别、脱壳简称、声明简称与位置登记。脱壳与查找函数从历史版本搬回并适配。

- 优点：纯本地规则与模型链路彻底分开，可单独测试；`ner引擎.py` 不再膨胀；改错范围小。
- 缺点：多一个模块，`_规则识别明显机构` 仍需从 `ner引擎` 取用。
- 改动面：新增 1 个模块，改 2 个调用点（脱敏处理器、app）。

### 方案二：把逻辑放回 `ner引擎.NER引擎`（历史位置）

- 优点：与旧结构一致，改动文件少一个。
- 缺点：`ner引擎.py` 刚瘦身完又被塞回数百行，模型转发与本地规则混在一起，测试要先构造引擎实例。

### 方案三：放进 `文档识别.py`，与 `识别文档` 并列

- 优点：不新建文件。
- 缺点：`文档识别.py` 主题是模型交互，混入无模型的正则流程后命名与职责都不清晰。

推荐方案一。

## 四、推荐方案设计

### 数据流

```
块列表
  └─ 正则机构识别.识别正则机构(块列表)
       1. 每块跑 _规则识别明显机构 → 机构全称 + 位置
       2. 全称注册机构项：{机构编号: {canonical: 全称, names: [全称]}}
       3. 脱壳：洗法律后缀与地名标记；公司、合伙类再洗行业词 → 简称，加入 names
       4. 声明简称：解析"（以下简称"××"）"，并入括号前的机构
       5. 在每块中定位全称与各简称的每次出现 → 出现记录(类型 Ni, 机构编号, 来源 "正则")
      → 识别结果（机构 dict + 出现 + 未完成）
  └─ 脱敏处理器：补固定规则 → 保存 → 跳过复查（跳过模型分支已存在）
```

`出现记录.类型` 用 `Ni`，`来源` 用 `"正则"`，`合并出现` 中正则项排序在模型项之后，优先级更低，符合预期。

### 脱敏处理器改动

`跳过模型` 为真时，把 `识别结果()` 换成 `识别正则机构(块, 模型进度)`；该字段名与语义升级为"只走纯正则"，界面下拉框选纯正则即置此字段。

### 界面改动

- `ctrl_card` 内新增"识别方式"下拉框，选项 `LLM（推荐）` 与 `纯正则`，默认 LLM，选择写入 settings。
- 选纯正则：跳过模型探测与可用性弹窗，直接进入处理。
- 选 LLM 且模型不可用：弹窗文案改为"模型不可用，是否改用纯正则（只脱敏机构及固定规则）"，选继续后置 `跳过模型 = True`，不再提示"机构名将被跳过"。

### 错误处理

- 全称不足 4 字或落在 `_兜底黑名单`：跳过，不登记。
- 脱壳简称不足 2 字：不登记。
- 同一简称同时匹配多个机构：保留首个登记，其余记入 `未完成`，不静默丢弃。
- 声明简称未找到对应前置机构：记入 `未完成`。
- 纯正则不处理人名与地址，处理结束后在日志与结果中明示：人名、详细地址未脱敏。

### 测试策略

- 单元：`识别正则机构` 对虚构短文，断言机构表内容与出现位置；含"（以下简称"××"）"用例断言简称并入同一机构；无后缀简称用例断言不误登记。
- 集成：`脱敏处理器` 纯正则模式处理 TXT，断言输出已脱敏、模型调用次数为零、映射表可分别还原全称与简称。
- 界面：沿用现有控件替身方式，断言下拉框默认 LLM、纯正则不触发探测。
- 回归：现有全部测试保持通过，LLM 链路行为不变。

### 迁移与回滚

改动集中在新增模块与两处调用点，不涉及数据格式变更，映射表格式不变。回滚只需恢复 `脱敏处理器` 与 `app.py` 两处调用。
