# Excel 读取优化设计

依据：[需求](../../requirements/2026-09-18-Excel读取优化-requirement.md)。用户已委托自主决策，实施于已有 main。

## 方案比较

| 方案 | 成本与兼容性 | 风险及验证 | 决定 |
|---|---|---|---|
| Excel 批量读取，每次启动 | 改动小，原生公式兼容性保持 | 单文件快，批量反复启动仍慢 | 不选 |
| Excel 批量读取，任务内复用 | 多一个资源管理类，无新增依赖 | 需验证异常、取消、原件及输出重读 | 选用，可局部回退 |
| 用 OfficeCLI 替换 | 新计算后端、错误与缓存语义需适配 | 常用公式通过不足以证明全部兼容 | 留待另行需求 |

## 设计追问及结论

复用范围只到一个处理任务，不跨线程、不跨任务保存全局对象。打开工作簿时仍只读，关闭当前文件后才打开下一文件；重读输出必须重新打开并复算，不能复用先前值。没有公式时不初始化 COM。初始化失败在本任务内记住，避免每份文件重复尝试不可用组件；工作簿个别失败不能阻止后续文件。

按工作表、列整理公式位置，每组最多覆盖 4096 行；稀疏行可在这个上限内合读，但只返回请求的坐标。Value2 一次取回该段，单格标量统一成行序列。Excel 错误码可能表现为整数，只对疑似错误码调用 ISERROR 核实，避免逐格 Text 调用，也不误伤正常负数。

解析 Excel 时按已存储且有值的单元格组织行，避免 iter_rows 为远距离单元格创建巨大空矩形。仅封装一处 openpyxl 已加载单元格存储访问，测试保护这个兼容边界。行与前三行表头上下文使用复算后的文本，原值及原公式仍独立保存。

## 数据流及接口

`处理文件列表` → `Excel公式读取会话`（惰性创建）→ `读取文档块(路径, Excel会话=会话)` → `读取Excel公式值(路径, 位置列表, 会话=None)` → 打开、重算、分块取值、关闭工作簿。原件、初次输出、补做输出走同一路径。会话退出关闭自己的 Excel 并释放 COM。

保留公开独立读取函数的双参数兼容用法；第三参数可选。新增读取模块承载资源生命周期，文档解析器及处理器只做接入。

## 错误处理

错误公式不返回成功值，解析器保留已有缓存或公式原文并标记具体位置。输出复查也须收集公式未完成标记，防止只有输入错误可见。工作簿关闭异常后不继续复用可能污染的实例；资源释放异常记录为未完成说明，已交付文件保留。取消检查发生于重算前后及分块前；Excel 正在进行的同步调用只能等返回。

## 术语与决策记录

沿用 CONTEXT 中的出现位置、逐文件独立、还原映射；补充“公式计算值”和“公式缓存值”，不改变主体建模。此决策可在模块和调用处局部撤回，不新增不可逆架构或外部依赖，不另建 ADR。

## 测试、迁移和回退

先以批量边界及资源释放受控测试看到失败，再实现；用本机 Excel 检验混合结果、公式错误、旧缓存、跨表及完整脱敏还原入口。以保留的相同合成样例计时，原件哈希不变。不改变配置、映射格式和 GUI 入口，无需迁移。回退只恢复 Excel 读取模块及调用，不回滚已完成的机构检测改进；所有修改前已有统一目录内已校验备份。
