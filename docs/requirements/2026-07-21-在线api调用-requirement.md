# 在线 API 调用功能 - 需求文档

> 创建日期：2026-07-21
> 状态：待用户确认
> 来源：用户提出"现在只能连本地 LM Studio，帮我增加功能可以调用在线 API，OpenAI 格式"

---

## 一、背景

当前工具的 NER（人名/地名/机构名识别）完全依赖本地 LM Studio。LM Studio 虽好，但有几个痛点：

1. **门槛高**——要装 LM Studio、下载模型（动辄几个 G）、加载模型、开服务器，零基础用户容易卡住
2. **吃硬件**——没有独立显卡或显存不够的用户，本地模型跑不动或慢得离谱
3. **准确率受限**——本地能跑的模型通常是 7B-14B 的小模型，对复杂机构名/简称的识别不如在线大模型

用户希望增加对**在线 API（OpenAI 格式）**的支持，让用户可以选择用在线大模型做 NER，解决上述痛点。

### 关键发现（调研得出）

- **LM Studio 本身就用 OpenAI 格式**（`/v1/chat/completions`），现有代码改造量比想象中小
- 现有 `mineru桥接.py` 里的 `探测lm_studio地址()`、`获取lm_studio模型列表()`、`探测lm_studio状态()` 都是针对本地写的
- 现有 `ner引擎.py` 的 `_调用llm()` 发请求时**没有带 Authorization 头**（本地不需要），这是接在线 API 必须补的
- 扫描版 PDF 的处理流程是：MinerU（独立 CLI）转文本 → NER 走 LLM。所以**MinerU 本身不需要改**，改造后扫描版 PDF 的 NER 部分自动受益于在线 API

---

## 二、需求描述

在保留本地 LM Studio 支持的前提下，增加对**任意 OpenAI 格式兼容的在线 API**的调用能力。用户可以在界面上切换"本地模式"和"在线模式"，同一时间只用一种。

### 用户选择的方案参数（来自阶段1澄清）

| 决策点 | 用户选择 | 说明 |
|---|---|---|
| API 提供商 | **自定义地址** | 不内置 OpenAI/DeepSeek/通义等预设，用户自己填 API 地址 |
| 本地/在线关系 | **同一时间只用一个** | 切换式，不是共存 |
| 配置入口 | **主界面加配置区** | 跟现有 LM Studio 端口框挨着 |
| 密钥存储 | **存 settings.json** | 跟 `lm_port` 同级，明文存储 |

## 三、边界条件

### 3.1 做的事

1. **界面切换**：主界面"LM Studio 配置"区改成"LLM 配置"区，顶部加切换控件（本地/在线二选一）
2. **在线配置区**：切换到在线模式时，显示 API 地址、API 密钥、模型名三个输入框 + 测试连接按钮
3. **配置持久化**：切换模式、修改任一配置项，立即保存到 `settings.json`
4. **后端适配**：`mineru桥接.py` 和 `ner引擎.py` 根据当前模式选择对应的 API 地址、鉴权方式、模型名
5. **状态检测**：启动时和切换模式时，根据当前模式检测对应后端的连通性，状态灯（绿/红）反映当前模式
6. **测试连接**：本地模式调 `/api/v0/models`（现状），在线模式调 `/v1/models` 带 `Authorization: Bearer {key}` 头

### 3.2 不做的事

- **不内置常见 API 提供商预设**（用户选了自定义地址）
- **不改 MinerU 引擎**（扫描版 PDF 转 text 的部分跟 LLM 后端无关）
- **不做多后端并发**（同一时间只用一个）
- **不改 NER 提示词和解析逻辑**（在线模型同样适用现有的严格解析+兜底解析）
- **不做 API Key 加密存储**（用户接受明文存 settings.json）
- **不做用量统计/费用提醒**（在线 API 收费，但本工具不负责监控）

### 3.3 隐含假设（grill-me 追问得出）

1. **用户能自己搞到 API 地址和模型名**——因为选了"自定义地址"，不预设常见厂商。UI 要给清晰的占位提示（如 `https://api.example.com/v1`）
2. **用户知道在线 API 收费**——每次脱敏都会调用 LLM，大文档可能花几毛到几块。在测试连接成功后给一次提示
3. **在线 API 都兼容 OpenAI 格式**——用户明确要求，不做 Anthropic 原生格式等其他格式
4. **settings.json 文件本身被视为安全**——用户接受明文存储，不做额外加密

### 3.4 边界场景（grill-me 追问得出）

1. **base_url 规范化**：用户可能填 `https://api.openai.com` 或 `https://api.openai.com/v1` 或带尾斜杠。程序要自动规范化，确保拼接出的 `/chat/completions` 路径正确
2. **模型名填写方式**：用户手填文本框 + 提供"拉取模型列表"按钮（点一下调 `/v1/models` 把可用模型填到下拉框）。拉取失败则退化为纯手填
3. **切换模式时正在脱敏**：禁用切换控件，提示"处理中无法切换"
4. **在线 API 超时**：沿用现有重试机制（2 次重试，间隔 3s/6s），超时后降级为纯正则模式（跟本地 LM Studio 不可用一样）
5. **在线 API 鉴权失败（401）**：明确提示"API 密钥无效，请检查"
6. **在线 API 模型不存在（404）**：提示"模型不存在，请检查模型名或点'拉取模型列表'查看可用模型"
7. **API Key 为空时点测试连接**：直接提示"请先填写 API 密钥"，不发请求

## 四、验收标准

### 4.1 界面

- [ ] 主界面"LLM 配置"区有"本地 LM Studio / 在线 API"切换控件
- [ ] 切换到本地模式：显示端口输入框 + 测试连接按钮（与现状一致）
- [ ] 切换到在线模式：显示 API 地址、API 密钥、模型名 + 拉取模型列表按钮 + 测试连接按钮
- [ ] 切换模式时配置区平滑切换，不卡顿
- [ ] 状态指示灯根据当前模式显示对应后端的连通状态

### 4.2 配置持久化

- [ ] 切换模式立即保存 `llm_mode` 到 `settings.json`
- [ ] 修改任一在线配置项（失焦时）保存到 `settings.json`
- [ ] 程序重启后自动恢复上次的模式和配置

### 4.3 功能

- [ ] 在线模式下填入正确配置后，点"测试连接"显示"已连接，可用模型数：N"
- [ ] 在线模式下点"拉取模型列表"，下拉框列出 `/v1/models` 返回的模型
- [ ] 在线模式下执行脱敏，日志显示 NER 调用在线 API 的过程
- [ ] 在线模式下脱敏结果正确（人名/地名/机构名被识别并替换为代号）
- [ ] 在线模式下扫描版 PDF 的 NER 也走在线 API（MinerU 部分不变）
- [ ] 本地模式所有现有功能不受影响（回归测试通过）

### 4.4 错误处理

- [ ] API Key 为空时点测试连接：提示"请先填写 API 密钥"
- [ ] API Key 错误（401）：提示"API 密钥无效"
- [ ] 模型名错误（404）：提示"模型不存在"
- [ ] 网络不通/超时：沿用现有重试+降级逻辑，提示"在线 API 不可用，降级为纯正则模式"
- [ ] 处理中点切换模式：禁用切换，提示"处理中无法切换"

### 4.5 安全

- [ ] API Key 明文存 `settings.json`（用户已接受）
- [ ] 测试连接成功后，给一次"在线 API 调用会产生费用"的提示
- [ ] API Key 输入框默认用密码框（显示为 `••••`），加一个"显示"勾选框切换明文

## 五、调研摘要

### 5.1 现有代码改造点

| 文件 | 函数/位置 | 改造内容 |
|---|---|---|
| `mineru桥接.py` | `探测lm_studio地址()` | 保留；新增 `探测在线api地址()` |
| `mineru桥接.py` | `获取lm_studio模型列表()` | 保留；新增 `获取在线api模型列表()`（带 Authorization） |
| `mineru桥接.py` | `探测lm_studio状态()` | 保留；新增 `探测在线api状态()` |
| `ner引擎.py` | `_获取api地址()` | 根据当前模式返回本地或在线地址 |
| `ner引擎.py` | `_检测lm可用性()` | 根据当前模式调用对应的检测函数 |
| `ner引擎.py` | `_调用llm()` | 在线模式下请求加 `Authorization: Bearer {key}` 头 |
| `ner引擎.py` | `_审核简称候选()` | 同上，加 Authorization 头 |
| `ner引擎.py` | `_MODEL` | 本地模式自动探测（现状）；在线模式读 settings.json 的 `online_model` |
| `app.py` | `build_ui()` 的 LM 配置区 | 改成"LLM 配置"区，加切换控件 + 在线配置输入框 |
| `app.py` | `_测试lm连接()` | 根据当前模式调用对应的测试逻辑 |
| `app.py` | `_检测lm状态()` | 根据当前模式调用对应的状态检测 |

### 5.2 settings.json 扩展结构

```json
{
  "llm_mode": "local",
  "lm_port": 1234,
  "online_api_base": "",
  "online_api_key": "",
  "online_model": ""
}
```

### 5.3 依赖

- **不新增任何依赖**。`requests` 库已支持 Authorization 头部，`customtkinter` 已支持密码框
- 所有改造复用现有依赖
