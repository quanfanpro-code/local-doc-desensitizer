# 纯正则机构脱敏需求（2026-10-23）

## 一、背景与问题

机构识别目前完全依赖大模型：`主程序/文档识别.py` 的 `识别文档` 对每个批次都要跑"发现"和"逐处核对"两轮请求，还要按机构分组重复请求，最后再做一次候选复核。结果是处理慢，且模型不可用时机构、人名、地址全部跳过，只剩手机号这类固定规则。

历史上存在过纯本地正则路线。初始版本 `2fbf1a0` 的 `文本脱敏` 中有"正则兜底：仅在 LLM 未产出实体时启用"：用后缀正则认出机构全称，再从全称脱壳生成简称，注册映射后全文替换。2026-09-18 机构识别重构成"模型结合上下文逐条判断"后，该能力降级为候选；2026-09-19 清理死代码时，相关函数被删除，当前代码中已无 `_清洗实体名`、`_洗行业词`、`_查找父实体`、`_发现简称候选`、`_合并简称声明`。

用户要求把这条路线恢复为可选项，由使用者在界面上自行选择。

## 二、用户与使用场景

使用者是本地处理涉密材料的审计、尽调人员，机器上不一定有可用模型。

- 场景一：不想等模型，或本机无模型。在主界面选"纯正则"，快速脱敏机构与固定格式信息。
- 场景二：选了 LLM，但接口连不上。弹窗选继续后走纯正则机构脱敏，而不是整批跳过。

## 三、功能范围

1. 主界面新增"识别方式"下拉框，选项为"LLM（推荐）"和"纯正则"，默认 LLM。
2. 纯正则模式下：
   - 机构全称：沿用现有 `_规则识别明显机构` 后缀正则与词典前缀清洗。
   - 简称来源两类：一是从全称脱壳，洗掉法律后缀与地名标记，公司、合伙企业再洗行业词；二是解析文档中"（以下简称"××"）"声明。
   - 固定规则照常执行，范围与现有开关不变（手机号、证件号、账号、车牌、日期、金额等）。
   - 人名、详细地址不处理，并在界面提示与结果中明示未处理范围。
   - 全程不调用模型，也不做模型可用性探测。
3. LLM 模式行为不变；模型不可用时弹窗文案改为"改用纯正则"，选继续后走纯正则机构脱敏，人名、地址同样明示未处理。
4. 机构全称与简称分别注册，可独立还原，沿用现有映射表与还原流程。

## 四、明确不做

- 不调整 LLM 识别链路本身，省 token 与缩短耗时是下一步工作。
- 纯正则不处理人名与详细地址。
- 不引入新依赖，不训练模型。
- 不改变固定规则的现有范围与开关。

## 五、约束与风险

- 脱壳简称会在全文替换，存在误伤风险，例如"小麦"既是机构简称又是粮食。旧版纯正则同样如此；本需求接受该风险，并在界面与说明中提示。
- 纯正则基于后缀与词典，识别不到的机构不会脱敏，例如无后缀简称、外文名称。
- 现有测试必须保持全绿，LLM 链路行为不得被破坏。

## 六、验收标准

1. 主界面存在"识别方式"下拉框，可切换 LLM 与纯正则，默认 LLM。
2. 纯正则模式处理一份含"某有限公司（以下简称"某某"）"字样的虚构文档：全称与简称均被脱敏，手机号等固定规则生效，过程中不产生任何模型请求。
3. 映射表可分别还原全称与简称。
4. LLM 模式下模型不可用时，弹窗选继续后机构被纯正则脱敏；此前该场景机构全部跳过。
5. 全部回归测试通过。
