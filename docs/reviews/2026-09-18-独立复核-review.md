## 三、新发现问题清单

### 🟡 X1. PDF 图片区域仍会被涂白（R1 的残留一半）

- **位置**：定位写回.py L204、L228；格式保持器.py `_既有映射PDF`——三处 `apply_redactions(graphics=0)` 都未传 `images`
- **事实**：本机 PyMuPDF 1.28.2 默认 `images=2`（PIXELS），与 redact 矩形重叠的图片像素被涂白。敏感文字压在扫描件插图、公章、图表上时，该图片区域出现白块
- **影响**：不泄露（白块反而遮盖更彻底），但破坏版面；readme 2026-07-21 曾将同类问题列为已修复
- **修复方向**：三处补 `images=pymupdf.PDF_REDACT_IMAGE_NONE`（与 graphics=0 并列）

### 🟡 X2. 请求硬编码 vLLM 私有字段，严格 OpenAI 后端会全部 400

- **位置**：文档识别.py L331 `请求模型`：`"chat_template_kwargs": {"enable_thinking": False}` 对每个后端都发送
- **事实**：该字段是 vLLM/Qwen 扩展，不属于 OpenAI 标准；OpenAI 官方等严格校验后端返回 400 "Unrecognized request argument"，会被 识别文档 标记为"服务不可用"导致整个文件机构识别停用（固定规则仍工作）
- **影响**：用户自用 vLLM 场景无碍；与"任意 OpenAI 格式兼容"承诺冲突
- **修复方向**：仅当 api_base 非官方域名时附加，或捕获 400 后去掉该字段重试一次

### 🟡（旧账仍在）Y1/Y2/Y5

- Y1 主线程探测冻结：改后台线程探测
- Y2 扫描版前置查 MinerU：start_desensitize 追加 `processor._ocr.是否可用()` 检查
- Y5 401/404 提示区分：探测函数返回状态码，GUI 按码给文案

### 🟡 X3. ner引擎.py 旧识别链路已成生产死代码（约 400-500 行）

- **事实**：重构后生产入口只有 文本脱敏 → 识别文档 新链路。以下成员在生产中无调用方，仅被测试或彼此引用：`识别实体`、`_调用llm`、`_构造白名单`、`_严格解析`、`_兜底解析`、`_提取json`、`_提取消息文本`、`NER_PROMPT`、`_分段`、`_审核简称候选`、`_审核PROMPT`、`_发现简称候选`、`_机构简称模式`、`_合并简称声明`、`_脱敏日期`、`_生成地址片段`、`_查找父实体`、`_清洗实体名`、`_洗行业词`，以及 BANK_ACCOUNT/CREDIT_CODE/MOBILE_PHONE/LANDLINE/ID_CARD/EMAIL/AMOUNT_PATTERN、DATE 两组模式、`_模糊化金额`（固定规则.py 只 import 了 PLATE/IPV4/MAC/AMOUNT_NO_UNIT 四个模式）
- **影响**：两套识别机制并存，维护者改一套忘一套的风险；test_ner引擎_跨块复用.py、test_ner引擎_在线模式.py 全在测死代码，给人"该链路仍在用"的错觉
- **修复方向**：删除旧链路成员 + 同步删除/改写上述两个测试文件（保留 _获取消息正式回答、_规则识别明显机构、_取词典 等被 文档识别.py 使用的成员）
