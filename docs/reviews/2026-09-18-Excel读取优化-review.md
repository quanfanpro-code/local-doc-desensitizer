## 实现和审查结论

- Excel 原生计算保持不变，公式按表、列分组，每段至多 4096 格 Value2；单格、多格、相距很远的公式均能取值。
- 同一次处理任务复用专属实例，原件、输出复查、补做重读共用；每个工作簿读完即关闭。没有公式不启动 Excel；正常复算无需再加载缓存工作簿。
- 稀疏表只读取已存储且有值的单元格，不用 iter_rows 填满空矩形。已将对 openpyxl 内部存储的依赖限于一处，并以 XFD1048576 稀疏边界回归保护。
- 原值和原公式保留，模型文字及表头、同行上下文使用计算值。0、False、空文本保持区别；疑似 COM 错误码通过 ISERROR 核实，避免把相同数值的普通负数错当错误。
- 原件只读，禁用宏、事件和链接更新。源哈希与还原验证通过。只对自建 Excel 调用 Quit，无进程级强杀、无修改用户 Excel 设置。
- 故障注入覆盖取消、计算失败、无法启动、无法打开个别文件、关闭失败和退出失败。无法启动在本任务内不反复尝试；个别文件打不开后下一份仍可读取；关闭失败停止复用并记录问题。
- 实际输出复算失败原先可能被当成完整成功，已先通过失败测试复现，再修复为保留输出及映射并记录未完成位置。

未引入 OfficeCLI 适配层、全局进程池、额外框架或通用重试机制；只保留解决当前批量读取问题所需的资源管理和分块。

同一天、同一台机器、相同输入文件，每组各 3 次取中位数，所有格逐一核对，13 个源文件哈希不变。旧数据来自本次实现前的正式逐格读取；新数据调用本次正式代码，不使用原型替代。

5000 个公式读取耗时减少约 **91.12%**。这些数字包含启动、打开、重算、取值及 Quit 调用，不包含后台进程最终退出等待，也不包含 LLM 识别耗时；不能推广为所有真实文件或整个脱敏流程同幅提速。新实现逐轮数据、输入哈希见 [效率记录](2026-09-18-Excel读取效率.json)。复测入口为 `维护工具/验证Excel读取效率.py`，自动生成合成样例并保留材料。

## 剩余边界

依然需要安装 Microsoft Excel 才能原生重算；外部数据不更新，无法计算时明确标记而不伪造结果。同步 COM 重算无法即时取消或从当前线程硬超时。超大工作簿仍需容纳 openpyxl 已存储单元格；4096 格限制针对跨进程取值，不能理解为整个程序内存上限。大量不同列的稀疏公式仍需要多段读取。
