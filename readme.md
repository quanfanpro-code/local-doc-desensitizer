# 本地文档脱敏工具

识别机构、人名、详细地址及固定格式敏感信息，生成脱敏文件和对应还原映射。支持 Windows、Python 3.10 及以上，实际改进验证使用 Python 3.14。

## 使用

1. 安装本机 Python，下载完整项目，双击“启动器.py”。启动器检查依赖，缺少时可安装 requirements.txt。
2. 在界面选择本地 LM Studio，或填写 OpenAI 兼容在线 API。在线模式会把文档中待分析文字发送到所填写的接口；本地模式使用当前已加载模型。本次真实评测使用用户指定的 Qwen3.8-27B，项目不内置接口密钥。
3. 点击“选择文件”或“选择文件夹”，按需选择输出目录，点击“开始脱敏”。
4. 结果文件与同名的“_脱敏映射表.json”一起保存。需要恢复时选择脱敏文件，点击“开始还原”，程序自动寻找对应映射。
5. 日志分别说明已生成文件、完整处理情况和未完成环节。模型某个环节失败时，已完成的替换与对应映射仍交付，不能把“生成了文件”理解为“所有内容检查完成”。

电话、邮箱、证件、账号、车牌、IPv4、MAC 始终参与固定格式检查。日期默认开启且只遮盖年份第3位；勾选“含精确月日”后日期整体用代号表示。金额默认关闭，开启后处理达到百万门槛的金额，银行家舍入到百万位，并保留币种，例如 123万美元 → 100万余美元。不同原值碰撞时分配可区分的代号。金额数字单元格结合本列金额字段及单位参加检查，普通数量不按金额处理；应结合业务用途选择金额开关。模型不可用时可选择仅使用固定规则，机构、人名和详细地址将跳过；文字 PDF 也支持这一选择。

## 文件支持与还原

| 格式 | 处理方式 |
|---|---|
| TXT、Markdown | 按确认的原文位置替换，保留各处实际写法 |
| Word .docx | 正文、表格、页眉页脚、脚注和尾注；跨文字节点只写一次，保留未命中文字样式 |
| Excel .xlsx | 数字、文字、公式计算值及双引号内文字常量分别检测，包含未执行分支；可定位常量直接改写并保留公式，敏感计算结果无法安全局部处理时只将命中格转为脱敏值；记录原公式和原类型用于还原 |
| PPT .pptx | 文本框、组合形状、表格及跨文字片段处理；保存文字节点以还原原写法 |
| 文字 PDF | 按具体字符位置移除并写入代号，避免清除框误伤邻行；保存后核对代号及该页未修改文字，无法安全处理时报错 |
| 扫描 PDF | 含大幅页面图像时即使已有文字层也输出脱敏 Markdown；复用可用文字层，否则调用配置的 OCR；不修改或还原原扫描图片版面 |

读取 Excel 公式实际结果需要本机 Microsoft Excel 和 pywin32；没有公式的工作簿不需要启动 Excel。同一批任务的原件读取、输出复查和补做后重读复用一个专属隐藏 Excel 实例，每份文件仍重新打开并计算。按有限区域批量取值，避免逐格跨进程读取；稀疏表只遍历已有且有值的单元格，不填满巨大空白区域。

原件只读，不更新外部链接，禁用宏与事件，任务结束关闭自己的 Excel。检测文字、表头和同行上下文使用重新计算的值，原公式另行保留用于还原。公式不能复算时可利用文件已有缓存继续部分处理，同时明确记录未完成位置；旧缓存不等于最新结果。输出复查失败同样会说明，不把生成文件当作完全成功。取消会在当前 Excel 调用返回后的检查点响应，正在执行的原生重算不能即时中断。

2026-09-18 本机对同一批合成样例各测 3 次，5000 个公式读取中位数由旧实现约 28.36 秒降到正式实现约 2.52 秒，耗时减少约 91%；10 个小文件共用实例约 2.97 秒。计时包括启动、打开、重算、取值和退出，不含模型识别时间；结果及原件哈希全部核对。可运行“维护工具/验证Excel读取效率.py”生成样例复测，详细记录见 [Excel 优化验收](docs/reviews/2026-09-18-Excel读取优化-review.md)。

旧版 .doc、.xls、.ppt 不支持，需先由 Office 另存为支持格式。

保存后重新读取实际输出，复查遗漏；能唯一对应回原文的遗漏按准确位置补做，不拿识别前的内存文字冒充实际输出。固定规则的覆盖问题需要修复输入或规则；只对临时连接、超时和可恢复服务错误有限重试。模型结构不合法会附具体错误进行纠正，不直接把思考草稿当正式答案。

原文件不被覆盖。已有同名输出覆盖前备份到当前用户 BackUp 文件夹并校验。Word/PPT/Excel 的新映射记录被改位置的原节点、原值和公式；若脱敏后文件又被修改，无法准确匹配的位置会明确报错。PDF 恢复原文字，字体、字距等不保证与原文件逐字节一致；代号较长时会调整字号，容纳失败会报告，不能把截断当成功。

新映射版本为 2，仍可读取旧的平面映射。旧映射曾把多个不同原词合用一个代号的，历史原词歧义无法凭空恢复。请妥善保存映射，其中包含敏感原文。

## 规则与词典

[规则来源说明](docs/规则来源.md)列明 datamask、Presidio、python-phonenumbers、JioNLP、Hutool 和原有地名字典的具体采用范围与来源。直接新增的依赖是 phonenumbers 9.0.39，默认地区 CN；没有把整套框架搬进来。

既有地名、行业词用于候选边界，审计普通词仅提示语境，不作为机构简称黑名单。身份证和信用代码采用校验；校验失败但字段明确时仍处理。银行卡校验不套用于全部对公账户。

### 2026-09-18 - 机构简称与全面脱敏改进

机构全称、任意简称、英文别称和一字代称现在按全文上下文识别。先整理当前文件的机构资料，再重新逐段核对所有原文；首次没发现的机构和简称仍可在第二轮补充。程序枚举简称每次出现以及漏项、矛盾项的准确位置，交给模型结合上下文逐条判断，不依靠重复运行相同正则补漏。

同一个词的不同出现分别处理。例如供应商“小麦”可以脱敏，而“采购小麦（粮食）”保持原文；母子公司、名称相似的机构及同名不同主体分别判断。全文没有提供全称，但明确指机构的简称也会独立脱敏，不编造全称。

全称和简称关联同一机构，保留不同原文写法。例如全称用 [公司1]，简称用 [公司1]①，重载映射后各自还原。每个文件独立识别、独立编号，文件之间不共享机构资料。

这些能力始终启用，原“简称强力审核”开关已由“机构简称自动核对”说明替代。日期、精确月日和金额仍各有原来的启用方式。

### 2026-09-03 - 简称声明合并（修复同一公司被拆成两个代号）+ 密钥安全加固

#### 🐛 修复的 bug

- 🐛 **同一公司被拆成两个代号**：文档里出现"某某公司（以下简称"某某集团"）"时，大模型会把全称和简称识别成两家独立公司，各发一个代号（如 [公司3] 和 [公司6]），脱敏后看起来像两家单位。原有的"父实体匹配"只认简称是全称里**连续的一段字**，简称的字被隔开（涌江集团 vs 涌江实业集团）、顺序不同（中石油 vs 中国石油天然气集团）或带了全称没有的字（本所、××所）时全部失效。新增"简称声明合并"机制：
  - **识别简称声明**：扫描"（以下简称"××"）"句式，兼容中英文括号、中英文引号、冒号等写法
  - **按声明认亲**：简称直接并入紧邻前文的机构代号，全文统一编号
  - **整体并户**：简称旧代号名下的所有变体（含脱壳别名）一并并入主代号，旧代号作废
  - **未登记简称也能挂靠**：如"本所"此前未被识别，直接登记到主实体代号下
  - **防误挂保护**：紧邻前文命中的不是机构类代号（如日期）时不合并；重复声明幂等

### 2026-07-09 — NER 输出链路全面加固：五层防御 + 质量闸门

#### 🔴 致命Bug修复

- 🐛 **思考型模型实体全丢**（核心）：qwen3.5 等 thinking 模型将全部输出塞进 `reasoning_content`，正式回答 `content` 为空字符串。旧版解析器从思考文本中捞 JSON，模型输出字段名不标准（用 `"text"` 而非 `"name"`），代码只认 `"name"` 字段 → 所有实体静默丢弃 → 映射表0个机构项，单位名称完全暴露。实测千问 3.5 9B 处理财务尽调报告，全部公司名未脱敏。现已五层防御：

1. **提示词强约束**：要求模型必须把最终 JSON 输出在正式回答 `content` 中，锁死字段只能是 `"name"`/`"type"`，类型只能是 `PERSON`/`LOCATION`/`ORGANIZATION`，禁止 Markdown/代码块/解释

- 🐛 **NER模型升级（SMALL → BASE）**：SMALL 模型准确率不足，长实体（如完整公司名）识别碎片化。升级为 **ELECTRA_BASE** 模型（~470MB），准确率大幅提升。实测和邦生物2025年报：SMALL 识别192个实体，BASE 识别585个，且公司名完整识别不再碎片化
- 🐛 **伪装文件格式导致崩溃**：旧版 `.doc` 文件被强行改扩展名为 `.docx` 时，程序内部解析崩溃报 `'Part' object has no attribute 'element'`。现已添加文件头魔数检测：打开文件前先读取前8字节判断真实格式，发现伪装时给出清晰的中文提示，不再抛出莫名其妙的错误

#### 🟠 严重问题修复

- 🔧 **transformers 5.x 兼容性**：`transformers 5.x` 将 `encode_plus` 方法改名为 `_encode_plus`（下划线前缀），HanLP 内部仍在调用旧名称导致 `AttributeError`。通过 monkey-patch `PreTrainedTokenizerBase.__getattr__`，在 HanLP 请求 `encode_plus` 时自动转发到 `_encode_plus`，无需降级 transformers
- 🔧 **HanLP 批处理输出解析**：HanLP 传入列表时返回单个 Document（非 list），NER 结果为嵌套列表 `[[实体1, 实体2], [实体3]]`。之前的代码按扁平列表解析，导致所有实体静默丢失。已重写解析逻辑，正确处理单条和批处理两种格式
- 🔧 **NER批处理性能优化**：从逐段推理改为每16段批量推理，推理次数从 ~480 次降至 ~30 次，大幅减少 CPU 推理开销
- 🔧 **LTP NER输出格式解析错误**：LTP 的 NER 输出为4元素元组 `(类型, 实体名, 起始, 结束)`，但代码按2元素 `(实体名, 类型)` 解析，导致全部实体静默丢失。该问题随LTP整体替换已一并解决
